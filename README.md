# SQLBackup

Утилита для автоматической обработки и доставки MSSQL-архивов резервных копий. Находит свежий файл бэкапа, переименовывает по шаблону, копирует на удалённый сервер с верификацией, удаляет исходный файл и отправляет HTML-отчёт по email.

## Возможности

- Поиск самого свежего файла бэкапа в заданной директории
- Переименование по настраиваемому шаблону с подстановкой текущей даты
- Асинхронное копирование с двойной буферизацией (4 МБ ping-pong)
- Инлайн-вычисление SHA-256 во время чтения (без второго прохода)
- Верификация скопированного файла по SHA-256
- Сохранение даты создания/изменения исходного файла
- Автоматическое удаление исходного файла после успешного копирования
- Настройка поведения при существующем файле назначения (перезапись/ошибка/суффикс/пропуск)
- Отправка HTML-письма через Exchange SMTP (AUTH LOGIN)
- Письма отправляются как при успехе, так и при ошибке
- Тема письма настраивается через конфиг с поддержкой переменных
- Шаблон письма — внешний HTML-файл (легко редактировать)
- Поддержка нескольких Backup-секций (`[Backup:DB1]`, `[Backup:DB2]`, ...)
- Подробное логирование: отдельный файл при каждом запуске, автоочистка старых логов
- Отладочный режим (без удаления исходного файла)

## Требования

- ОС: Windows 7 / Windows Server 2008 R2 и выше
- Компилятор: MSVC 2019+ (Visual Studio 16 2019 / 17 2022)
- Система сборки: CMake 3.15+
- Зависимости: только Windows SDK (Winsock2, CryptoAPI)

## Сборка

```cmd
cmake -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
```

Исполняемый файл: `build\Release\SQLBackup.exe`

## Конфигурация

Файл `config.ini` размещается рядом с `SQLBackup.exe`. Альтернативный путь — через аргумент `-c`.

```ini
[General]
NameTemplate = backup_{date}
DateFormat = %d.%m.%Y
FileExtension = .bak
Debug = false
OnExists = 1
; ServerName = SRV-BACKUP-01

[Backup:DB1]
SourcePath = C:\Backups\DB1
DestPath = \\server1\share\DB1

[Backup:DB2]
SourcePath = C:\Backups\DB2
DestPath = \\server2\share\DB2
NameTemplate = archive_{date}

[General]
SourcePath = C:\Backups\SQL
DestPath = \\server\share\Backups

[Mail]
Server = exchange.company.local
Port = 25
SenderName = SQL Backup Service
SenderEmail = backup@company.local
Recipients = admin@company.local, dba@company.local
Auth = false
Username =
Password =
TemplatePath = mail_template.html
Subject = [{STATUSJOB}] Backup [{LABEL}] on {SERVERNAME}

[Log]
LogPath = C:\Logs\SQLBackup
MaxLogs = 30
```

### Параметры

#### `[General]`

| Параметр | Описание |
|---|---|
| `SourcePath` | Путь к папке с файлами бэкапов (fallback для `[Backup:*]`) |
| `DestPath` | Путь назначения, локальный или UNC (fallback для `[Backup:*]`) |
| `NameTemplate` | Шаблон имени, `{date}` заменяется на дату (fallback) |
| `DateFormat` | Формат даты в стиле `strftime` (по умолчанию `%d.%m.%Y`) |
| `FileExtension` | Расширение искомых файлов (по умолчанию `.bak`) |
| `Debug` | Отладочный режим — исходный файл **НЕ** удаляется (`true`/`false`) |
| `OnExists` | Поведение при существующем файле назначения: 1 — перезаписать, 2 — ошибка, 3 — суффикс `_001`..`_999`, 4 — пропустить |
| `ServerName` | Имя сервера для подстановки `{SERVERNAME}`; если не указано — определяется как FQDN |

#### `[Backup:<имя>]`

Каждая секция — отдельная задача копирования. `SourcePath` и `DestPath` обязательны.
Остальные параметры наследуются из `[General]`, если не указаны в секции.

#### `[Mail]`

| Параметр | Описание |
|---|---|
| `Server` | Адрес Exchange / SMTP-сервера |
| `Port` | SMTP-порт (обычно 25 или 587) |
| `SenderName` | Отображаемое имя отправителя |
| `SenderEmail` | Email отправителя |
| `Recipients` | Список получателей через запятую |
| `Auth` | Включить SMTP-аутентификацию (`true`/`false`) |
| `Username` | Логин для SMTP |
| `Password` | Пароль для SMTP |
| `TemplatePath` | Путь к HTML-шаблону письма (по умолчанию `mail_template.html`) |
| `Subject` | Тема письма с поддержкой переменных (см. ниже) |

#### `[Log]`

| Параметр | Описание |
|---|---|
| `LogPath` | Папка для логов |
| `MaxLogs` | Максимальное количество хранимых логов |

## Шаблон письма

Письмо формируется из внешнего HTML-файла. Путь задаётся параметром `TemplatePath` в секции `[Mail]` (по умолчанию — `mail_template.html` рядом с exe).

### Переменные шаблона

| Переменная | Описание |
|---|---|
| `{STATUSJOB}` | Статус выполнения: `Успешно` / `Ошибка` |
| `{STATUSCLASS}` | CSS-класс для стилизации: `success` / `error` |
| `{SERVERNAME}` | Имя сервера (из конфига или FQDN) |
| `{LABEL}` | Метка секции (`DB1`, `General`, ...) |
| `{FILENAME}` | Имя файла |
| `{FILESIZE}` | Размер файла (ГБ/МБ/КБ/Б) |
| `{SOURCEPATH}` | Полный путь к исходному файлу |
| `{DESTPATH}` | Полный путь к файлу назначения |
| `{SOURCEURL}` | `file:///` URL исходного файла |
| `{DESTURL}` | `file:///` URL файла назначения |
| `{COPYDATE}` | Дата и время копирования |
| `{COPYDURATION}` | Длительность копирования + верификации |
| `{ERRORTABLE}` | HTML-таблица с описанием ошибки (пусто при успехе) |
| `{ERRORMESSAGE}` | Текст ошибки для подстановки в тему письма (пусто при успехе) |

Переменные `{STATUSJOB}`, `{STATUSCLASS}`, `{SERVERNAME}`, `{LABEL}`, `{FILENAME}`, `{FILESIZE}`, `{COPYDATE}`, `{COPYDURATION}`, `{ERRORMESSAGE}` поддерживаются как в теле, так и в теме письма (`Subject`).

### Outlook

Шаблон оптимизирован для корректного отображения в Outlook (табличная вёрстка, `width="640"`, HTML-атрибуты `cellpadding`/`cellspacing`). Ошибка отображается в отдельной таблице, ширина которой привязана к контейнеру письма.

```cmd
SQLBackup.exe
SQLBackup.exe -c C:\path\to\config.ini
SQLBackup.exe --help
```

### Аргументы командной строки

| Аргумент | Описание |
|---|---|
| `-c <path>` / `--config <path>` | Путь к файлу конфигурации |
| `--help` | Показать справку |

## Алгоритм работы

1. Загрузка конфигурации из INI-файла
2. Инициализация логгера, очистка старых логов
3. Для каждой секции `[Backup:*]` (или `[General]`):
   - Поиск самого свежего файла с заданным расширением в `SourcePath`
   - Генерация нового имени по шаблону с текущей датой
   - Переименование исходного файла
   - Копирование в `DestPath` (асинхронное, с инлайн-SHA-256)
   - Верификация скопированного файла по SHA-256
   - Сохранение временных меток исходного файла
   - Удаление исходного файла (если не Debug)
   - Отправка HTML-письма (успех или ошибка)
4. Очистка старых логов
5. Завершение с соответствующим кодом возврата

## Классификация ошибок

При сбое в письмо подставляется описание в `{ERRORMESSAGE}` / `{ERRORTABLE}`:

| Ситуация | Текст ошибки |
|---|---|
| Не задан SourcePath | `Не указан путь к исходной папке (SourcePath)` |
| Нет файлов по маске | `Не найден файл резервной копии в папке: ...` |
| Переименование | `Не удалось переименовать файл — файл с именем "..." уже существует` |
| Копирование | `Ошибка копирования — не удалось записать файл назначения (проверьте место на диске и права доступа)` |
| Верификация | `Ошибка верификации — контрольная сумма SHA-256 не совпадает, файл назначения повреждён` |

## Логирование

При каждом запуске создаётся файл `SQLBackup_YYYYMMDD_HHMMSS.log` в папке, указанной в `LogPath`. При превышении `MaxLogs` самые старые логи автоматически удаляются.

## Поведение при существующем файле

Параметр `OnExists` в `[General]` регулирует реакцию, если файл назначения уже существует:

| Значение | Поведение |
|---|---|
| `1` (по умолчанию) | Перезаписать |
| `2` | Ошибка — секция помечается как failed |
| `3` | Добавить суффикс: `_001`, `_002`, ... `_999` |
| `4` | Пропустить — запись в лог, секция считается успешной |

## Требования к правам

Утилита запускается от имени пользователя, имеющего:
- Права на чтение исходной папки и удаление файлов
- Права на запись в сетевую папку назначения
- Доступ к SMTP-серверу (если используется аутентификация — соответствующий логин/пароль)
